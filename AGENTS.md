# Инструкции для работы с rust-file-manager

## Устройство проекта

Это self-hosted файловый менеджер на Rust 2021 / Actix Web с несколькими пользователями. В проекте нет AI API и отдельной сборки фронтенда. Добавляйте их только для функции, которой они необходимы.

- `src/main.rs`: запуск сервера, маршруты, middleware сессий, встроенные шаблоны и миграция старого расположения файлов.
- `src/files.rs`: списки и метаданные файлов, скачивание с авторизацией, загрузка, переименование и удаление. Здесь формируются данные шаблона.
- `src/auth.rs`: вход, регистрация, проверка сессии и прав администратора.
- `src/users.rs`: пользователи и одноразовые приглашения; сохранение в `users.json`.
- `src/config.rs`: настройки из окружения и ключ подписи cookie.
- `src/categories.rs`: допустимые категории и проверка компонентов пути.
- `templates/*.html`: русский интерфейс, встроенные CSS и JavaScript. Шаблоны включаются через `include_str!`; после изменения нужна пересборка бинарника.
- `xtask/`: команды версий и выпуска. `build.rs`: метаданные сборки.
- `deploy/` и инструкции развёртывания: примеры для существующих VPS.

Минимальная заявленная версия Rust — 1.88, в соответствии с закреплёнными зависимостями. Сохраняйте развёртывание одним бинарником.

## Данные и права доступа

Хранилище: `UPLOAD_DIR/shared/<категория>/` и `UPLOAD_DIR/home/<пользователь>/<категория>/`. Имя владельца личной зоны берите из сессии, не из параметров запроса. Сохраняйте авторизацию всех файловых маршрутов и проверку администратора для управления участниками. Старые cookie удалённых пользователей не должны давать доступ.

Сохраняйте данные и существующее расположение папок. Не перезаписывайте файлы при совпадении имён; удаляйте неполные загрузки. Проверяйте категории и компоненты пути на сервере. При изменении работы с файлами и пользователями учитывайте симлинки, одновременные запросы и сбои сохранения. Экранируйте текст и кодируйте каждый сегмент URL отдельно.

Не читайте, не выводите в логи, не переносите в тесты и не коммитьте настоящие `.env`, `users.json`, загруженные файлы, пароли, приглашения и ключи сессий. Проверяйте приложение на отдельных синтетических данных. Примеры команд в документации сами по себе не разрешают развёртывание, удаление данных или замену секретов.

## Интерфейс

Пользовательский текст — на русском. Проверяйте компьютер, планшет и телефон, включая ширину 320 px. Не допускайте горизонтального переполнения. Поддерживайте длинные имена, Unicode, пробелы, `#`, `?`, `%`, `+` и кавычки.

Используйте семантическую разметку, связанные подписи полей, видимый фокус, понятные названия действий для экранных дикторов и читаемые ошибки. Размер сенсорной кнопки — не менее 44 px. Подтверждайте удаление, выводите ошибки в соответствующем диалоге. Для пользовательского текста используйте `textContent`; не вставляйте имена файлов в HTML или JavaScript. Скачивание должно работать без JavaScript. Хранилище браузера и Clipboard API — необязательные удобства; предусматривайте резервный вариант, в том числе для HTTP через Tailscale.

Ясно различайте личную и общую зоны. Поясняйте, что ссылки требуют входа, а личные файлы доступны владельцу. При ошибке загрузки сохраняйте выбранные файлы и не повторяйте отправку уже подтверждённых сервером файлов. Для обычных улучшений не добавляйте CDN, внешние шрифты, фреймворки или телеметрию.

## Проверки и рабочий процесс

Перед правками проверяйте `git status --short`, сохраняйте чужие изменения. Делайте целевые правки; сохраняйте публичные маршруты и имена полей JSON, если задача не требует их замены.

Команды из корня проекта:

```sh
cargo test --workspace --locked
cargo check --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

При доступном кэше и отсутствии сети добавляйте `--offline`. Для проверки форматирования используйте `cargo fmt --all -- --check`. В исходном коде есть прежние расхождения форматирования: не форматируйте посторонние файлы, изменённый файл обрабатывайте командой `rustfmt --edition 2021 <файл>`.

Добавляйте регрессионные тесты для изменённой проверки доступа, путей, удаления неполных загрузок, совпадения имён и сохранения данных. Интерфейс проверяйте на реально отрисованном шаблоне: разные ширины, клавиатура, ошибка и повтор загрузки, переименование и удаление, поиск и сортировка, вход и виды администратора/участника. Указывайте выполненные проверки и ограничения.

Для локального сервера используйте временное хранилище и тестовые учётные данные. Не подключайте предпросмотр к рабочим данным. Выпуск через `cargo xtask release`, развёртывание, изменение версии, коммиты и отправку в Git выполняйте по запросу пользователя.
