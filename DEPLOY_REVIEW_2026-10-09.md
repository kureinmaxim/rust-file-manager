## Исправленное поведение

| Проблема | Результат |
|---|---|
| В пустом VPS всегда выбирались оба проекта | В терминале выбор `both`, `bot`, `fm`; `--only` и заранее заданные параметры имеют приоритет |
| Обновление запускалось без интерактивного плана | В терминале выбор проекта, вопрос об архиве FM и подтверждение; `--yes` выполняет без вопросов |

| `--only` всё равно менял связку и второй проект | Отдельное обновление изолировано; настройка связки выполняется обычным `deploy` |
| Ошибки nginx/пересоздания бота могли завершиться успехом | Возвращается ошибка; итог не обещает непроверенную работу кнопки «Файлы» |

| Остановленная служба считалась актуальной | Та же версия перезапускается и проверяется |
| FM не обновился, но зависимый бот продолжал обновляться | FM откатывается; обновление бота откладывается |
| EOF мог создавать бесконечный опрос | Быстрый отказ с подсказкой; неполные `--ref` и `--only` также отвергаются |
| Самообновление перезаписывало скрипт без копии | Прежняя команда сохраняется; замена атомарная; setup отказывается перезаписывать чужие команды |
| Токен показывался частично и вводился открыто | Скрытый ввод, сообщения только о наличии токена; добавлены `WARNING` комментарии |

| Новый .env мог быть доступен другим пользователям | Новый файл создаётся с правами 600 до записи секретов |
| Ключ FILES уже есть, а адреса отсутствуют/пустые | Недостающие адреса заполняются без дублирования ключей и с копией env |
| Запрошенная архивация данных не удалась, обновление продолжалось | Старая служба запускается, программа не заменяется, возвращается ошибка |

## Что требуется на настоящем VPS

Это проверка кода и сценариев, а не реальное развёртывание. Реальные DNS,
сертификаты/Cloudflare, приватный GitHub, ресурсы VPS, сеть контейнера и
Telegram/BotFather нужно подтвердить на выбранном сервере.
Автоматический откат FM возвращает программу; он не откатывает миграции
данных. Автоматический откат Docker-образа бота не реализован.

Неполная или нестандартная старая установка требует отдельного плана
восстановления с реальными путями. Перед включением нового ufw на работающем
сервере необходимо согласовать порты существующих служб.

Алгоритм действий — [DEPLOY_ALGORITHM.md](DEPLOY_ALGORITHM.md).
Копии изменённых исходных файлов сохранены локально в игнорируемом
`_local/deploy-review-backups-20261009/`; секреты туда не копировались.

Проверено исключение локальных копий, вспомогательных скриптов аудита,
рабочих env и пользовательских данных из Git. Файлы с рабочими секретами
не читались и не изменялись. Настройки сканеров и проверки безопасности
не менялись. В коммиты включаются только проверенные файлы; локальные
копии и секреты в индекс не добавляются. Для автора коммитов используется
публичный GitHub-псевдоним и адрес noreply вместо личной почты.

Для повторной локальной проверки текущего набора перед commit/push:

```powershell
python _local/audit_deploy_privacy.py --gate
```

Команду запускайте из checkout rust-file-manager на этой машине. Скрипт
локальный, игнорируется Git и проверяет оба checkout. При находках он
возвращает ошибку и сообщает только файл, строку и категорию; значения
секретов не выводит. Это дополнительная эвристическая проверка, она не
заменяет существующие сканеры и просмотр окончательного списка файлов.
Не используйте `git add -f` для локальных копий или файлов с секретами.

Обезличивание текущих документов не удаляет прежние значения из уже
опубликованной истории GitHub. История в рамках этой проверки не переписывалась.
