# Мини-приложение «Файлы» в Telegram

Файловый менеджер открывается внутри Telegram: кнопка «Файлы» в чате с ботом →
мини-приложение по адресу `https://files.example.com/tg/`. У автора это бот
TelegramOnly (приватный репозиторий); свой бот подключается так же — раздел 5.
Вход без пароля — по подписи Telegram; пароль нужен один раз, чтобы привязать
Telegram к существующему аккаунту (или регистрация по приглашению).

Установка и обновление файлового менеджера — [DEPLOY.md](DEPLOY.md),
[POST_DEPLOY.md](POST_DEPLOY.md); бота эти команды не ставят и не трогают.
Макет экранов: [design/miniapp-mockup.html](design/miniapp-mockup.html).

## Что уже работает

- Привязка Telegram к аккаунту по логину и паролю (5 попыток за 15 минут),
  регистрация по одноразовому приглашению (`t.me/<бот>?startapp=inv_…`).
- Главная: занятое место по категориям, недавние файлы.
- Мои и общие файлы: категории, **подпапки**, «хлебные крошки», поиск по
  именам во всех вложенных папках, сортировка, список и сетка с миниатюрами.
- Загрузка с телефона и компьютера, в том числе с камеры: файл уходит частями
  (по умолчанию 8 МБ), обрыв связи не начинает загрузку заново, повторный выбор
  того же файла продолжает её с места остановки. Лимит файла —
  `MAX_CHUNKED_FILE_SIZE_MB` (по умолчанию 4 ГБ), лимит Cloudflare 100 МБ на
  запрос не мешает.
- Карточка файла: открыть (фото — встроенный просмотр со свайпами; видео, аудио
  и PDF — во внешнем просмотрщике), скачать нативным диалогом Telegram,
  переименовать, удалить. Новая папка, переименование и удаление папки.
- Настройки: завершить другие сеансы, отвязать Telegram.
- Внутренний API для бота: `/files_status`, `/files_invite`, `/files_bind`,
  кнопка «Файлы» у привязанных пользователей.
- С 1.5.1 те же подпапки видны и в обычном веб-интерфейсе: дерево папок,
  «Новая папка», «Загрузить сюда», переименование и удаление пустых папок.
  Там же кнопка «Переместить» переносит файл между общими и своими файлами,
  категориями и папками.
- С 1.6.0 — **«Обмен»** между администратором и каждым участником, в браузере
  и в мини-приложении. Участник видит экран «Обмен» с вкладками «Входящие» и
  «Отправленные» и кнопкой «Отправить администратору»; администратор — список
  участников со счётчиками присланного. Файл можно открыть, скачать,
  сохранить копией в «Мои файлы» или удалить (у обоих). Отправка идёт той же
  очередью загрузок частями, с докачкой. На главной — плашка «Администратор
  прислал файлы». Хранение: `UPLOAD_DIR/exchange/<участник>/from-admin|from-user/`.
- С 1.8.0 файловый менеджер ставится на VPS командой `deploy` и обновляется
  командой `post_deploy` ([POST_DEPLOY.md](POST_DEPLOY.md)); бот ставится и
  обновляется своими средствами.
- С 1.7.0 бот TelegramOnly (3.25.0+) **присылает уведомление** получателю,
  когда в обмен пришёл файл: «📥 Администратор прислал вам файл…» с кнопкой
  «Открыть обмен», которая открывает мини-приложение сразу на нужном экране.
  Нужен только внутренний API (раздел 5 ниже); выключается в боте
  `FILES_NOTIFY=false`, частота опроса — `FILES_NOTIFY_MINUTES` (10 минут).
  Диалог скачивания Telegram показывает настоящий размер файла.
- С 1.10.0 — **файлы через чат с ботом** (бот TelegramOnly 3.27.0+, раздел 6):
  кнопка «В чат» в карточке файла присылает его в личку с ботом, а файл или
  фото, отправленные боту, сохраняются в «Мои» или «Общие файлы».
- С 1.13.0 — **загрузка с компьютера по QR-коду** (раздел 7): страница
  `https://files.example.com/pc` в браузере компьютера, телефон сканирует код в
  «Загрузки» → «С компьютера», и файлы, перетащенные в окно браузера, попадают в
  «Мои файлы» по типу. Экраны загрузок показывают, **сколько места свободно** на
  сервере, лимит одного файла и **сколько осталось ждать**; файл, который не
  поместится, отмечается сразу, а загрузку дольше часа экран предупреждает.

**Пока нет** (следующие этапы плана): корзина — удаление сейчас **окончательное**,
удалить можно только пустую папку; перемещение в мини-приложении и копирование; редактор
текстов; публичные ссылки и запросы файлов; выбор папки при сохранении из чата.

## 1. Telegram (BotFather)

1. Узнайте числовой ID бота — это число **до двоеточия** в его токене
   (`7000000001:AA…` → `7000000001`). Сам токен файловому менеджеру не нужен.
2. `/mybots` → бот → **Bot Settings → Configure Mini App → Enable Mini App** →
   URL `https://files.example.com/tg/`. Это главное мини-приложение бота: кнопка
   «Открыть» в профиле и ссылки `t.me/<бот>?startapp`.

**Один адрес — один бот.** Вход принимается только из бота с номером
`TELEGRAM_BOT_ID`. Если у вас несколько серверов с файловым менеджером, у
каждого свой бот, и в BotFather адрес сервера указывается только у его бота.

Мини-приложение открывается только по **HTTPS** с действительным сертификатом
(Cloudflare или Let's Encrypt, см. [DEPLOY.md](DEPLOY.md)).

## 2. Настройки rust-file-manager

Добавьте в `/etc/rust-file-manager/env` (комментарии — отдельными строками):

```ini
MINIAPP_ENABLED=true
TELEGRAM_BOT_ID=7000000001
TELEGRAM_BOT_USERNAME=files_example_bot
PUBLIC_BASE_URL=https://files.example.com
UPLOAD_CHUNK_SIZE_MB=8
MAX_CHUNKED_FILE_SIZE_MB=4096
# сколько места на диске загрузки не занимают (с 1.13.0)
UPLOAD_RESERVE_MB=512
```

`UPLOAD_RESERVE_MB` — запас свободного места для системы, журналов и бота.
«Свободно для загрузок» = свободное место на диске − этот запас − то, что ещё
должно прийти в незавершённые загрузки. Файл больше этого сервер не принимает
(ответ 507) — до начала загрузки, а не после часа передачи.

`SESSION_SECRET` обязателен на практике: из него выводятся ключи токенов
мини-приложения и подписанных ссылок. Без него каждый перезапуск выкидывает
всех из мини-приложения (оно молча переоткроет сеанс, но ссылки на скачивание
устареют).

Перезапуск и проверка:

```bash
sudo systemctl restart rust-file-manager
sudo journalctl -u rust-file-manager -n 5 --no-pager -o cat | grep 'starting server'
# ожидается miniapp=true
curl -s -o /dev/null -w '%{http_code}\n' https://files.example.com/tg/
# ожидается 200
```

## 3. nginx

Если используете [deploy/nginx.example.conf](deploy/nginx.example.conf), перенесите
из него в свой виртуальный хост два блока: `location /api/v1/uploads/` (части
загрузки без буферизации на диск) и `location /d/` (подписанные ссылки не пишутся
в журнал доступа — в пути лежит токен). Затем `sudo nginx -t && sudo systemctl reload nginx`.

В Cloudflare включите **Bypass cache** для `/api/*` и `/d/*`.

## 4. Первый вход

Откройте мини-приложение (кнопка «Открыть» в профиле бота или ссылка
`https://t.me/files_example_bot?startapp`). Появится экран «Свяжите Telegram с
аккаунтом»: введите логин и пароль файлового менеджера. Администратор входит
логином `ADMIN_USERNAME` и своим паролем — так его Telegram становится
«администратором файлов», и бот сможет выдавать приглашения.

## 5. Связка с ботом

Бот ходит во внутренний API файлового менеджера. Если бот работает в Docker
(сеть bridge), API доступен ему через socat-мост на шлюзе docker-сети. Ниже —
пример для бота автора (TelegramOnly); свой бот подключается так же: ему нужны
адрес мини-приложения, адрес внутреннего API и ключ `INTERNAL_API_TOKEN`.

1. В `/etc/rust-file-manager/env`:

   ```ini
   INTERNAL_BIND_ADDR=127.0.0.1:8091
   # openssl rand -base64 48 | tr -d '\n'
   INTERNAL_API_TOKEN=<не менее 32 символов>
   ```

   `sudo systemctl restart rust-file-manager`; в журнале — `internal API for the bot enabled`.
2. Мост: поправьте адрес шлюза в [deploy/rfm-internal-bridge.service](deploy/rfm-internal-bridge.service)
   (`docker network inspect <проект>_default`), затем

   ```bash
   sudo apt install -y socat
   sudo install -m 0644 deploy/rfm-internal-bridge.service /etc/systemd/system/
   sudo systemctl daemon-reload && sudo systemctl enable --now rfm-internal-bridge
   ```

   Firewall: разрешите вход на порт 8091 только с интерфейса docker-сети.
   Наружу порт не открывайте; nginx его не проксирует.
3. В настройках бота (у TelegramOnly — `.env`, имена переменных ниже — его):

   ```env
   FILES_MINIAPP_URL=https://files.example.com/tg/
   FILES_INTERNAL_URL=http://172.18.0.1:8091
   FILES_SERVICE_TOKEN=<тот же INTERNAL_API_TOKEN>
   ```

   и перезапуск бота с новыми настройками (у TelegramOnly — `bash scripts/rebuild_bot.sh`).
4. Проверка из Telegram (у TelegramOnly): `/files_status` — версия, диск, участники. У
   привязанных пользователей слева от поля ввода появляется кнопка «Файлы»;
   ввод «/» по-прежнему показывает список команд.

## 6. Файлы через чат с ботом

Работает, когда включён внутренний API (раздел 5): без `INTERNAL_API_TOKEN`
кнопки «В чат» в мини-приложении нет. Обе стороны используют тот же ключ.

- **Из хранилища в чат.** «В чат» ставит задание в очередь в памяти файлового
  менеджера (до 5 на пользователя, живёт 10 минут). Бот забирает его long-poll
  запросом `GET /internal/v1/jobs?wait=25`, скачивает файл
  (`GET /internal/v1/jobs/<id>/content`) и отправляет в личку **тому, кто нажал**.
  Bot API принимает от ботов файлы до 50 МБ; больше — бот пишет, что файл
  нужно открыть в приложении.
- **Из чата в хранилище.** Бот скачивает присланный файл из Telegram (облачный
  Bot API отдаёт ботам до 20 МБ) и передаёт его в `POST /internal/v1/files` с
  Telegram ID отправителя. Файл получает только привязанный аккаунт; категория
  выбирается по расширению, одноимённый файл не перезаписывается, имя от Telegram
  очищается от путей. Лимит — `MAX_FILE_SIZE_MB`.

Права проверяются там, где запрос появился: у мини-приложения — по его токену,
у бота — по привязке Telegram ID. Своему боту достаточно реализовать эти вызовы
внутреннего API (`src/chat.rs`).

## 7. Загрузка с компьютера (QR-код)

Для больших файлов и папок с фото удобнее компьютер: телефон в фоне может
прервать загрузку, а браузер на ПК — нет. Телефон и компьютер не обязаны быть в
одной сети или соединены кабелем: оба ходят на сервер через интернет.

1. На компьютере откройте `https://files.example.com/pc` — страница покажет
   QR-код и код вида `ABCD-2345` (действует 5 минут, потом обновится сам).
2. На телефоне: «Файлы» → «Загрузки» → «С компьютера» → «Сканировать QR-код».
   Подойдёт и обычная камера телефона: код — это ссылка
   `https://t.me/<бот>?startapp=pc_ABCD2345`, она откроет мини-приложение.
   В Telegram на компьютере сканера нет — там «Ввести код».
3. Телефон показывает, какой компьютер просит доступ («Chrome · Windows» и код),
   и после «Подключить» страница на компьютере сама переходит к загрузке.
4. Файлы перетаскиваются в окно или выбираются кнопкой и уходят в «Мои файлы»,
   категория по типу файла — как при загрузке с телефона. Той же очередью частями,
   с докачкой: если связь оборвалась или сервер перезапустился, подключитесь снова
   и выберите тот же файл — загрузка продолжится с места остановки.

Подключённые компьютеры видны на том же экране телефона, у каждого — «Отключить».
Подключение закрывается само через 30 минут без загрузок и не позже чем через
12 часов; до 5 компьютеров на аккаунт.

Ничего настраивать не нужно: `/pc` и его запросы идут через тот же `location /`
nginx, части файлов — через `location /api/v1/uploads`. `PUBLIC_BASE_URL` задаёт
адрес, который телефон предлагает открыть на компьютере.

## Безопасность

- **Компьютер получает только загрузку.** Это схема OAuth device flow
  (RFC 8628): код на экране лишь называет запрос, а токен получает только
  страница, которая его создала (по своему секрету). Токен компьютера (`pc1.…`)
  принимают только `/api/v1/uploads` и `/api/v1/pc/session`: он не видит списков
  файлов, не получает ссылок на скачивание, не трогает «Общие файлы», «Обмен»
  и папки, а незавершённые загрузки видит только свои. Подтверждение кода — только
  из мини-приложения владельца, 10 попыток за 10 минут; код из 8 символов
  (40 бит) за 5 минут не подобрать. «Отключить», «Завершить другие сеансы» и
  отвязка Telegram сразу отключают и компьютеры. Страница `/pc` не встраивается
  в чужие сайты (`frame-ancestors 'none'`) и не загружает внешних скриптов.
- Файловый менеджер **не хранит токен бота**: `initData` проверяется по
  Ed25519-подписи Telegram и числовому ID бота.
- Токен сеанса мини-приложения живёт только в памяти страницы, 12 часов;
  «Завершить другие сеансы», отвязка Telegram и удаление пользователя сразу
  отзывают все его токены и ссылки на скачивание.
- Ссылки на скачивание подписаны, привязаны к одному файлу, живут 5 минут
  (просмотр и потоковое видео — 6 часов). Встроенный показ — только для
  безопасных типов (фото, видео, аудио, PDF); SVG и HTML всегда скачиваются.
- Пути проверяются на сервере: запрещены `..`, служебные имена, симлинки;
  глубина подпапок — до 8.
- CSP страницы мини-приложения разрешает только собственные файлы и скрипт
  Telegram; встраивание — только в web.telegram.org.

## Если что-то не так

| Сообщение | Причина и что сделать |
|---|---|
| «Данные Telegram не прошли проверку подписи» | `TELEGRAM_BOT_ID` не совпадает с ботом, через которого открыто приложение (часто — адрес этого сервера указан в BotFather у другого бота), или бот из тестового контура Telegram — тогда `TG_TEST_ENV=true`. В журнале: `journalctl -u rust-file-manager \| grep 'rejected Mini App initData'` → `reason=BadSignature` |
| «Клиент Telegram не передал подпись» | Обновите Telegram: поле `signature` есть в клиентах с Bot API 8.0 и новее |
| «Сеанс Telegram устарел» | Приложение было открыто больше `TG_INIT_DATA_MAX_AGE_SECS` назад — закройте и откройте снова |
| Загрузка падает на первой части с 413 | `client_max_body_size` в nginx меньше `UPLOAD_CHUNK_SIZE_MB` (+ запас 1–2 МБ) |
| «На сервере не хватает места» | Файл больше, чем «Свободно для загрузок»: освободите диск или уменьшите `UPLOAD_RESERVE_MB`. Незавершённые загрузки держат место до отмены или суточной очистки |
| `/pc` открывает вход на сайт | Мини-приложение выключено: страница работает только при `MINIAPP_ENABLED=true` |
| «Код не найден или устарел» | Код живёт 5 минут и срабатывает один раз — обновите страницу `/pc` и отсканируйте новый |
| На телефоне нет кнопки «Сканировать QR-код» | Сканер есть только в Telegram для iOS и Android; в остальных — «Ввести код» |
| `/files_status`: «файловый менеджер отклонил токен бота» | `FILES_SERVICE_TOKEN` бота ≠ `INTERNAL_API_TOKEN` |
| `/files_status`: «файловый менеджер недоступен» | Не запущен `rfm-internal-bridge`, неверный шлюз в `FILES_INTERNAL_URL` или не задан `INTERNAL_BIND_ADDR` |

## Разработка

Debug-сборка принимает `TG_DEV_PUBLIC_KEY` — свой Ed25519-ключ вместо ключа
Telegram, чтобы открывать `/tg/` в обычном браузере с подписанным тестовым
`initData`. **Release-сборка эту переменную игнорирует.** Фронтенд лежит в
`miniapp/` без шага сборки (Preact + htm, см. [miniapp/VENDOR.md](miniapp/VENDOR.md))
и вшивается в бинарник при `cargo build`.
